# TRON 光轮游戏重构与扩展（TRON Light-Cycle Game Refactoring & Extensions）

一个基于 JavaFX 的经典街机游戏 TRON 的维护与扩展项目，通过系统性的代码重构、设计模式应用和功能增强，将遗留代码转化为可维护、可扩展的高质量软件系统。项目涵盖 MVC 架构迁移、设计模式实现、JUnit 测试、Maven/Gradle 构建以及完整的文档与演示。

## 项目概述

本项目基于一个可运行但代码质量欠佳的 TRON 游戏遗留代码库，目标是运用软件设计原则与模式提升可维护性，同时添加创新游戏功能。项目强调专业软件开发实践，包括 Git 版本控制、分支管理、文档驱动开发和自动化测试。

## 技术栈

- **语言**：Java（JavaFX）
- **IDE**：IntelliJ IDEA
- **构建工具**：Maven 或 Gradle
- **版本控制**：Git（GitLab csprojects）
- **测试框架**：JUnit
- **文档**：Javadoc、Markdown
- **演示**：MP4 屏幕录制

## 核心任务

### 1. Git 专业使用（20%）

| 实践 | 要求 |
|------|------|
| **提交信息** | 清晰、描述性的 commit messages |
| **推送与合并** | 有效的 push 和 merge 操作 |
| **分支管理** | 熟练运用分支进行功能开发与 bug 修复 |
| **Issues/Labels/Milestones** | 高质量使用项目管理功能 |
| **.gitignore** | 合理配置，排除 `.jar` 等可执行文件 |

### 2. 代码重构（40%）

#### 基础维护（及格要求）
- 编写信息丰富的 README 和 Javadoc
- 将源文件组织到有意义的包结构中
- 重构大类以遵循设计原则（SOLID）和模式

#### 高阶重构（高分要求）
- **MVC 模式**：实现 Model-View-Controller 架构分离
- **设计模式应用**：至少实现 5 种不同设计模式（Observer 必须自定义实现，禁止使用 JavaFX 内置监听器）
- **构建工具**：使用 Maven 或 Gradle 确保项目可成功构建
- **JUnit 测试**：为重构和新增类编写有意义的测试用例

### 3. 功能扩展（10%）

#### 基础功能（及格要求）
- **主菜单界面**：游戏图片背景 + 三个按钮
  - START → 进入游戏
  - OPTION → 8+ 背景颜色选项列表
  - INFO → 游戏信息说明
- **得分弹窗**：每轮结束后显示回合得分

#### 高阶功能（加分项）
- **高分历史记录**：显示玩家姓名、日期、其他详情，游戏结束后持久化存储到文件
- **创新关卡设计**：原创或灵感启发的有趣游戏关卡
- **创新游戏机制**：独特的玩法功能增强

### 4. 文档（20%）

#### README.md（≤1000 词，不含测试用例和表格）

**附加功能说明**（最多评估前 5 个）：
- 功能是什么、在游戏中的作用
- 实现该功能的具体类和关键方法

**设计模式说明**（最多评估前 5 个，不含 MVC）：
- 应用理由（解决什么问题、提升灵活性、降低耦合）
- 实现该模式的具体类和方法

**软件测试摘要**（如实现）：
- 高层测试计划（目标、测试类型、环境）
- 测试用例表格（测试名、被测类/方法、输入/前置条件、预期结果、实际结果、测试框架）

#### Javadoc
- 全面的类描述
- 方法的 `@param`、`@return` 等完整标签
- 清晰的 API 参考

#### 高层类图
- 仅包含类和接口（不含方法/属性）
- PDF 格式，展示最终项目结构

### 5. 演示视频（10%）

**10 分钟 MP4 屏幕录制**，必须依次覆盖：

1. **最终游戏演示**
   - 游戏玩法、核心功能、机制和用户体验

2. **开发过程与 Git 使用**
   - Git 历史展示专业实践
   - 分支使用方式
   - Milestones、Labels、Issues 的项目管理应用
   - 关键 commit 的变更理由说明

3. **文档概览**
   - 高层类图解释（架构与设计模式）
   - Javadoc 展示（内容完整性）

4. **个人贡献**
   - 明确突出个人在代码、重构、文档和功能开发中的贡献

5. **README 内容验证**
   - 每个设计模式：解释 "Why"（应用理由）和 "Where"（具体类/方法）
   - 每个附加功能：解释 "What"（功能描述）和 "Where"（具体类/方法）

## 设计模式要求（自定义 Observer）

- **Observer 模式**：必须**自定义实现**，禁止使用 JavaFX 内置事件监听器（如 `InvalidationListener`）
- 其他可选模式：Factory、Strategy、Decorator、Singleton、Command 等
- 每种模式需提供：应用理由 + 具体实现位置

## 项目特点

- **真实遗留代码**：在可运行但质量欠佳的代码基础上进行重构
- **设计驱动**：从混乱代码到遵循 SOLID 原则和 MVC 架构的演进
- **模式实践**：强制自定义 Observer，深入理解设计模式本质
- **全栈文档**：README + Javadoc + 类图 + 视频，多维度展示工作
- **专业 Git**：分支策略、Issue 管理、Milestone 规划，模拟工业级协作
- **测试文化**：JUnit 测试作为质量保障，与重构同步进行
- **创新空间**：在基础功能之上自由发挥创意，添加独特游戏机制
