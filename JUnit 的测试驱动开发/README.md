# 忠诚度系统积分累积模块测试驱动重构（Loyalty Points TDD Refactoring）

一个基于 JUnit 的测试驱动开发（TDD）项目，针对"混乱代码库"进行系统性测试设计与代码重构。项目通过理解、测试、修复三步走，将开发者 Parker 留下的低质量积分累积代码转化为功能正确、结构清晰、测试覆盖充分的可靠模块。

## 项目概述

本项目承接 Coursework 1 的"In-the-Wild Bean"忠诚度系统，聚焦于积分累积（Point Accrual）功能。开发团队负责人 Tara 指派团队通过测试先行策略理解现有代码，识别缺陷，逐步修复并重构。质量经理 Eliot 期望看到严格的测试实践、详细的变更记录和良好的团队协作证据。

## 技术栈

- **语言**：Java
- **测试框架**：JUnit（超越基础 `@Test` + `assertEquals`）
- **版本控制**：GitLab（CSprojects）
- **协作工具**：GitLab Issues、Milestones、Labels、Boards
- **开发模式**：测试驱动开发（TDD）

## 项目背景

开发者 Parker 在**无计划、无沟通**的情况下编写了积分累积代码，质量堪忧：
- 代码结构混乱，充满不规则性
- 部分代码可能无法运行
- 缺乏设计一致性，疑似"故意写坏"

团队目标：**不恢复全部原始需求**，而是聚焦现有代码，使其**功能正确且经过良好测试**。

## 核心任务

### 第一阶段：测试计划（Test Planning）

基于 `CW2-ClassDescription.md` 类描述文档，制定严格的测试计划：

- 使用 Markdown 表格模板规划测试用例
- 考虑边界值、异常输入、状态转换
- 团队可自由扩展表格行列

**团队协作设置**：
- 建立 GitLab 仓库，配置 Milestones、Labels、Issues
- 通过 Issues 分配任务、追踪进度、关闭已完成项
- 实时更新 Issue 状态，保持团队信息同步

### 第二阶段：JUnit 测试开发（核心评估项）

为三个 Java 类编写全面的 JUnit 测试：

| 类 | 阶段 | 难度 |
|----|------|------|
| `User` | Stage 1（Lab 07） | 基础 |
| `PurchaseRecord` | Stage 1（Lab 07） | 基础 |
| `Main` | Stage 2（Lab 08） | 集成测试，较难 |

#### 测试质量要求

| 要求 | 说明 |
|------|------|
| **多样化断言** | 使用 `assertTrue`、`assertFalse`、`assertNull`、`assertThrows` 等，不局限于 `assertEquals` |
| **参数化测试** | 使用 `@ParameterizedTest` 减少重复代码 |
| **逻辑覆盖** | 测试覆盖函数中的条件分支（if/else、switch、循环边界）|
| **超越显而易见** | 不仅测试"正常路径"，更要测试边界、异常、非法状态 |
| **作者标注** | 每个测试方法的注释中明确标注开发者姓名（结对编程时两人均需署名）|

### 第三阶段：代码修复与重构（次要任务）

在测试引导下修复和优化代码：

- **记录失败**：文档化测试失败原因、修复内容、通过时间
- **变更追踪**：代码注释中记录修改内容、修改者、修改原因
- **交叉引用**：Java 代码注释中引用相关测试，解释"为何如此修改"
- **重构加分**：改进代码结构（提取方法、消除重复、优化命名）并详细注释

## 测试报告规范

团队需提交详细的 Markdown 测试报告，超越给定模板：

### 报告内容要求

1. **团队策略与决策**
   - 测试优先级排序方法
   - 任务分工与协作模式
   - 不同任务的责任人

2. **测试表格扩展**
   - 增加"重要性评级"列
   - 增加"测试目的"列
   - 增加"失败原因"列（若未通过）
   - 增加"修复措施"列（记录代码变更使测试通过）

3. **通过/失败日志**
   - 每条测试的通过日期
   - 初始失败时的诊断信息
   - 最终通过的验证记录

## 评分维度

| 维度 | 权重 | 核心评估点 |
|------|------|------------|
| **JUnit 测试质量** | 主要 | 覆盖率、严谨性、断言多样性、参数化测试、逻辑覆盖深度 |
| **测试报告详细度** | 次要 | 失败记录、修复追踪、团队策略、扩展表格 |
| **软件工程实践** | 三级 | 代码修复与文档化、版本控制使用、GitLab Issues 管理 |
| **代码重构** | 加分 | 结构改进、注释一致性、测试交叉引用 |

## 项目特点

- **测试先行**：强制 TDD 思维，先理解预期行为再修复代码
- **混乱代码挑战**：在真实"烂代码"上实践，培养阅读和维护他人代码的能力
- **团队协作深度**：GitLab Issues/Milestones/Labels 的完整使用，模拟工业协作
- **质量意识**：不仅关注测试通过，更关注测试的严谨性与覆盖深度
- **重构导向**：最高加分项是结构性改进，而非简单补丁
- **变更可追溯**：详细的注释记录谁改了什么、为什么改、对应哪个测试
