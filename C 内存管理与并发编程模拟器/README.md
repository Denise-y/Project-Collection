# 内存管理与并发编程模拟器（Memory Management & Concurrent Programming Simulator）

一个基于 C 语言的系统级编程项目，模拟操作系统核心机制：内存分配算法与多线程生产者-消费者同步。项目通过链表实现动态内存块管理，结合 POSIX 线程与计数信号量，完整复现了操作系统底层的资源调度与并发控制逻辑。

## 项目概述

本项目以 Linux 环境为运行平台，模拟操作系统内存管理子系统的核心功能。分为两大核心模块：**Task 1** 实现内存分配策略与碎片整理，**Task 2** 扩展为多线程并发环境下的生产者-消费者模型，使用信号量与互斥锁保证线程安全与数据一致性。

## 技术栈

- **编程语言**：C (C11)
- **编译工具**：GCC
- **并发库**：POSIX Threads (pthread), POSIX Semaphores (semaphore.h)
- **运行环境**：Linux (csubuntu)
- **构建方式**：Makefile / 手动编译

## 核心功能

### Task 1: 内存分配算法实现

模拟 1MB 总内存空间（1KB 最小单位），使用双向链表追踪已分配与空闲内存块：

| 算法 | 策略说明 | 适用场景 |
|------|----------|----------|
| **Next Fit** | 从上一次分配位置开始线性搜索，选择第一个足够大的空闲块 | 低分配开销，适合内存请求分布均匀的场景 |
| **Worst Fit** | 选择最大的空闲块进行分配，保留较大剩余碎片 | 减少小碎片产生，适合大中小请求混合场景 |

**内存压缩（Compaction）**：
- 当分配失败时触发碎片整理
- 将所有已分配块向内存起始端移动，合并尾部空闲空间为单一连续大块
- 更新所有被移动块的指针与链表结构

**健壮性处理**：
- 分配失败时请求进入等待队列（Bounded Queue）
- 支持重复的分配/释放操作与边界条件检查

### Task 2: 多线程生产者-消费者模拟

基于 Task 1 的内存系统，扩展为多线程并发架构：

**生产者线程（Producers）**：
- 生成随机内存分配请求（2–50 KB）
- 将请求存入共享有界缓冲区（Shared Bounded Buffer）
- 使用计数信号量控制缓冲区“不满”条件

**消费者线程（Consumers）**：
- 从缓冲区取出请求并执行分配/释放操作
- 使用计数信号量控制缓冲区“不空”条件
- 记录操作日志：线程 ID、操作类型、内存块地址与大小

**线程安全机制**：

| 同步原语 | 保护对象 | 作用 |
|----------|----------|------|
| **Counting Semaphore (`not_full`)** | 缓冲区槽位 | 防止生产者向满缓冲区写入 |
| **Counting Semaphore (`not_empty`)** | 缓冲区数据 | 防止消费者从空缓冲区读取 |
| **Mutex (`stats_lock`)** | 共享统计变量 | 保证全局计数器（总生产数、总消费数、成功/失败分配数）的原子更新 |

**共享统计信息**：
- 总生产请求数（Total Produced）
- 总消费请求数（Total Consumed）
- 成功分配次数（Successful Allocations）
- 失败分配次数（Failed Allocations）

> 注：由于 C 语言中自增操作非原子性，所有统计更新必须在互斥锁保护的临界区内完成，防止竞态条件导致数据不一致。

## 关键设计决策

### 内存分配策略对比
- **Next Fit** 通过维护上一次搜索指针降低平均搜索时间，但可能导致内存末尾堆积碎片
- **Worst Fit** 优先使用最大空闲块，意图保留足够大的中间碎片供后续大请求使用，实际效果依赖请求分布

### 并发同步设计
- 采用 **计数信号量** 而非二元信号量，直接表达缓冲区资源的可用数量，语义更清晰
- 将缓冲区同步（信号量）与统计信息同步（互斥锁）分离，避免过度锁定导致的性能瓶颈

### 内存压缩的时机选择
- 仅在分配请求无法满足时触发压缩，而非每次释放后执行，平衡了碎片整理开销与内存利用率

## 项目特点

- **系统级视角**：从操作系统原理出发，手动实现内存管理器而非调用标准库 `malloc/free`
- **并发安全**：完整应用生产者-消费者模型与信号量机制，处理竞态条件与死锁预防
- **算法对比**：在同一框架下实现多种分配策略，直观对比其碎片率与性能差异
- **工程规范**：代码需在 Linux/GCC 环境下编译通过，注重注释清晰与结构模块化，符合学术代码评审标准
